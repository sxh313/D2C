# 固定输入样例

这里包含 3 个截图输入和 3 个 Spec 输入，取自本机真实任务的输入快照。反馈表单和任务页截图来自本项目生成页面；任务看板图来自历史任务输入，其原始制作来源未记录。`manifest.json` 中的 SHA-256 用于核对输入文件，历史任务 ID 仅用于查阅原机器上的记录，不能在其他机器恢复历史任务。

## 使用

1. 按照 [项目使用与验收记录](../../项目使用与验收记录.md) 中的“首次准备”和“启动和停止”启动工作台。
2. 选择一个目录：截图样例上传 `reference.png`；Spec 样例将 `spec.txt` 内容粘贴到 Spec 输入框。
3. 将同目录 `instruction.txt` 的内容粘贴到指令框；文件为空时无需填写。`spec-tabs/checks.json` 记录原任务的可选标签验收规则：标签名称“已完成”、初始文本“整理需求文档”、切换后文本“完成界面设计”。如需复用，在工作台对应的标签验收字段手动填写，JSON 不是导入文件。
4. 核对资料后创建任务；重新生成会调用配置的模型，产生新的运行结果和可能的费用。
5. 查看构建、检查与预览结果，按需要修改并人工核对页面。原任务的结果见根目录《固定样例验收记录.md》，不能作为新任务通过的证明。

这些文件只复现输入，不包含运行结果、依赖、模型配置或凭据。模型输出可能变化；截图以外的隐藏交互不能仅凭截图确定。Figma 样例需要可访问的实际节点和 Bridge，会话不在此包内；输入组合的历史证据和限制见 [项目使用与验收记录](../../项目使用与验收记录.md)。
